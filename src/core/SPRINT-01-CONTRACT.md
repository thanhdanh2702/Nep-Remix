# Sprint 01 Core contract

Consumer handoff (additive API; Leader review before Frontend integration).

- `Gate = { all: Requirement[] }`; requirements discriminate on `kind`: `puzzleSolved {puzzleId}`, `dialogueCompleted {dialogueId}`, `itemOwned {itemId}`. Optional `when` on puzzle/hotspot/dialogue; `area.exitGates[exitName]` protects the existing string-valued `exits`. Legacy prerequisitePuzzleIds remain AND requirements. `isGateSatisfied` is exported. Side maps phai/trai to mat_phai/mat_trai.
- `puzzle/submit {puzzleId, answer}` and `item/use {itemId,targetPuzzleId}` share guard/evaluator/outcome. Required multi-item answers are arrays of unique owned IDs with exact set equality; single item/use cannot satisfy them. Action-only use requires the exact action token. Present requires owned evidence. Wrong typed/incorrect answers produce puzzleFeedback, leaving state unchanged; inaccessible puzzles reject with ok:false/reason. No public solve/skip shortcut.
- `ChapterProgress.dialogueQueue?: string[]` contains pending IDs excluding activeDialogue, deduplicated in trigger order. Advance/choose acknowledges the CURRENT node and grants its clue; merely opening it never does. Final acknowledgement completes and promotes the next queued dialogue. Reopening the same active dialogue keeps its node/history. Reload preserves both.
- Completion requires the current unlocked chapter, every declared puzzle and completionDialogueId acknowledged. `reward/claim` atomically unions every catalog reward and adds Sen once. `museum.unlockedCardIds?: string[]` means available, never read/claimed. `claimedRewardIds?: string[]` uses reward.id; legacy journey.claimed remains supported.
- Save key remains tiem-may-nep-save-v1. Envelope gains contentVersion. fromJSON migrates all historical snapshots; legacy claimed rewards repair missing noncurrency gifts without adding Sen. Original bytes are preserved under SAVE_KEY + '-backup' before replacing a migrated save. Corrupt/unsupported saves are not overwritten by autosave. saveGame remains boolean for existing UI; restoreGame adds status and reason without removing tree/notice/hasSave.
- Design-dependent C1 gate/content, loan wardrobe and replay changes await the approvals identified in team-sprint-01.md. No C2–C5 JSON changes.
